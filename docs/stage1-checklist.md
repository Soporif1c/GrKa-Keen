# Проверка этапа 1 на роутере (KN-1811)

Установка альфы с GitHub (pre-release `v1.0.0-alpha.1`):

    sh -c "$(curl -fsSL https://raw.githubusercontent.com/Soporif1c/GrKa-Keen/release-1.0/install.sh)" _ v1.0.0-alpha.1

Без GitHub: скопировать `grka-keen-1.0.0-alpha.1.tar.gz` в `/opt/tmp` и выполнить:

    tar -C / -xzf /opt/tmp/grka-keen-1.0.0-alpha.1.tar.gz
    sh /opt/share/grka/bin/grka migrate && /opt/etc/init.d/S99grka-keen restart

Чтобы ниже писать просто `grka`, один раз в сессии SSH:

    alias grka='sh /opt/share/grka/bin/grka'

## Основное

1. `grka status` — «Состояние: ok», политика найдена, правила на месте, TUN поднят.
2. Открыть панель `http://<IP роутера>:1100`: вкладки «Статус», «Селекторы», «Конфигурация», «Логи» открываются, на «Статусе» есть строка «Сторож» и кнопка «Поставить VPN на паузу». Если панель открывается по имени (не по IP), добавьте имя в `allowed_hosts` в `/opt/etc/grka/settings.json`.
3. Перезагрузить роутер три раза. После каждой загрузки `grka status` и `grka logs journal 30`: в журнале «Политика «GrKa» найдена», «Правила маршрутизации применены», «Ядро mihomo запущено», состояние ok.
4. Отключить и включить интернет в веб-интерфейсе Keenetic. Через 10 секунд `grka status` — ok.
5. `kill -9 $(cat /tmp/grka/core.pid)` — через 10–20 секунд ядро снова работает, в журнале «упало, перезапуск через 5 с».
6. `grka pause` — интернет у устройств политики идёт напрямую; `grka resume` — снова через ядро.

## DNS и DoT/DoH

7. `iptables -t nat -S GRKA_DNS` — строки только с IP игровых устройств (без них цепочки нет). DNS обычных устройств не перехватывается и идёт через DoT/DoH роутера.
8. Если установлен tcpdump (`opkg install tcpdump`): `tcpdump -ni <WAN-интерфейс> port 53` (часто `ppp0` или `eth3`), на обычном устройстве открыть несколько сайтов — вывод пустой: открытого DNS к провайдеру нет.
9. `iptables -t nat -S PREROUTING | head -n 3` — сразу после строки `-P PREROUTING ACCEPT` идёт `-A PREROUTING -j GRKA_DNS` (если есть игровые устройства). Если переход не первый, прислать вывод целиком.

## Игровые устройства

10. `grka device <MAC приставки> gaming`, затем `ip rule` — есть правила 97 и 98 с IP приставки; `iptables -t nat -S GRKA_DNS` — две строки с этим IP.
11. На приставке проверить тип NAT (PS5: «Настройки → Сеть → Проверить соединение с интернетом»; Xbox: «Сеть → Тип NAT»): NAT 2 или «Открытый».
12. Сменить IP приставки (зарезервировать другой адрес в Keenetic и переподключить её) — в течение минуты `ip rule` показывает правила 97/98 с новым IP, старого нет; в журнале «Адреса игровых устройств».
13. Выключить приставку — в течение минуты правила 97/98 с её IP пропадают. Включить — возвращаются. Если правила не появляются, когда приставка в сети, прислать `curl -s http://127.0.0.1:79/rci/show/ip/hotspot` (в ответе важно поле `active` у приставки).

## Кнопки и ошибки

14. «Остановить» в панели, затем перезагрузить роутер — при включённом «Автозапуске» ядро запускается само.
15. Четыре раза `kill -9 $(cat /tmp/grka/core.pid)`, каждый раз дождавшись перезапуска, — состояние «ошибка», в журнале «повторы остановлены». Кнопка «Запустить» в панели — ядро снова работает.
16. «Проверить обновления» на вкладке «Статус» — кнопка «Обновить панель» неактивна: последний стабильный релиз 0.0.2 старше альфы.
17. Если в Keenetic включён IPv6: `ip -6 rule` — правило 99 с `prohibit`. Без IPv6 в статусе нет предупреждений про IPv6.
18. `grka diag` — прислать получившийся файл (токены в нём скрыты, у MAC видна только первая половина).
